# История просмотров MrBeast

Приложение на TypeScript собирает **число просмотров** публичных видео основного канала [MrBeast](https://www.youtube.com/@MrBeast) через официальный YouTube Data API v3. Первый сбор выполняется сразу после запуска, последующие — **каждые 5 минут**. История сохраняется в локальной SQLite, в том числе после перезапуска.

Видео отслеживается, пока его возраст меньше `TRACKING_WINDOW_DAYS` (по умолчанию **14 дней**). В момент достижения этого срока новые записи прекращаются; уже собранная история остаётся в базе. В расчётах используются точные временные метки UTC: 14 дней — это 336 часов с момента публикации, а не две календарные недели.

## Запуск

Нужен **Node.js 24.19+**; проверенная версия указана в `.node-version`. SQLite встроена в Node.js; отдельный сервер базы данных и зависимости для рабочего приложения не требуются.

```sh
npm ci
cp .env.example .env
# Укажите YOUTUBE_API_KEY в .env
npm run build
npm start
```

В Google Cloud создайте проект, включите [YouTube Data API v3](https://console.cloud.google.com/apis/library/youtube.googleapis.com), затем создайте ключ в [разделе Credentials](https://console.cloud.google.com/apis/credentials). Ограничьте ключ этим API. Для чтения публичного канала OAuth и вход в YouTube не нужны. Ключ указывается локально в `.env` или в переменных среды хостинга; `.env` исключён из Git. Приложение передаёт ключ в HTTPS-заголовке, а не в URL, и исключает его из сообщений об ошибках.

Для облачной среды разрешите HTTPS-запросы к `www.googleapis.com`. Секрет можно добавить через настройки среды как `YOUTUBE_API_KEY` для этого домена. Команды запуска учитывают `HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY` через встроенную поддержку прокси Node.js; проверка TLS остаётся включённой. Во время разработки:

```sh
npm run dev
```

Остановка — `Ctrl+C` или `SIGTERM`. Расписание действует, пока процесс запущен. Для непрерывного сбора на сервере используйте менеджер процессов или сервис хостинга с автоматическим перезапуском и сохраняйте каталог `data/` на постоянном диске. После изменения `.env` перезапустите процесс.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `YOUTUBE_API_KEY` | — | Ключ YouTube Data API v3; необходим для сбора |
| `TRACKING_WINDOW_DAYS` | `14` | Максимальный возраст видео в днях; допустимы положительные дробные значения |
| `POLL_INTERVAL_MINUTES` | `5` | Интервал получения числа просмотров в минутах |
| `FULL_DISCOVERY_INTERVAL_MINUTES` | `60` | Интервал полного обхода списка загрузок канала |
| `DATABASE_PATH` | `./data/mrbeast.sqlite` | Файл SQLite; относительный путь считается от текущей рабочей директории |
| `YOUTUBE_CHANNEL_ID` | `UCX6OQ3DkcsbYNE6H8uQQuVA` | Идентификатор основного канала MrBeast |

Значение 14 вынесено в `DEFAULT_TRACKING_WINDOW_DAYS` в `src/config.ts`. Переменная среды позволяет менять срок без изменения кода. При увеличении срока сбор возобновляется для подходящих видео, включая ранее исключённые по возрасту; при уменьшении прекращается для видео за новой границей. Историю за пропущенный период восстановить нельзя.

## Команды и результаты

```sh
npm run collect       # Один сбор и завершение процесса
npm start -- --help   # Справка
npm run check         # Проверка типов, тесты и сборка
```

Каждый успешный цикл печатает JSON-сообщение `collection_completed`: время наблюдения, число видео-кандидатов, число сохранённых наблюдений и число пропущенных кандидатов. Ошибки выводятся в stderr; после сбоя сервис продолжает работу на следующем цикле. Разовый запуск при ошибке завершается с ненулевым кодом. Запросы имеют таймаут и повторяются при сетевых сбоях, HTTP 429 и 5xx. При превышении суточной квоты потребуется дождаться её сброса или увеличить квоту Google Cloud.

Экспорт всей сохранённой истории в CSV не требует API-ключа:

```sh
npm run --silent export > views.csv
```

Колонки: `video_id`, `channel_id`, `title`, `published_at`, `observed_at`, `view_count`. Число просмотров хранится как точная целочисленная строка, без округления JavaScript. База содержит таблицы `videos` (метаданные) и `view_snapshots` (история). Записи одного цикла сохраняются в транзакции; при сбое запроса частичные результаты не записываются. Повторная запись с тем же видео и временем наблюдения не создаёт дубликат.

## Как работает сбор

1. Через `channels.list` находится плейлист загрузок канала; его идентификатор кешируется на время процесса.
2. На каждом цикле проверяется первая страница последних загрузок. При запуске и раз в час обходятся **все страницы** плейлиста: порядок загрузок может отличаться от дат публичной публикации. Это позволяет найти свежие видео и за первой страницей. Новая публикация там может быть обнаружена с задержкой до интервала полного обхода.
3. Для найденных видео и уже отслеживаемых видео запрашиваются дата публикации и число просмотров через `videos.list` партиями до 50 идентификаторов. Уже отслеживаемые видео проверяются каждые 5 минут, независимо от полного обхода плейлиста.
4. Перед записью возраст проверяется повторно по `snippet.publishedAt`. Ровно в 14 дней видео исключается. Будущие публикации, предстоящие премьеры, непубличные, удалённые и недоступные видео пропускаются. Shorts и текущие публичные трансляции учитываются, если API возвращает число просмотров.

Значения — те, которые возвращает YouTube API: они могут обновляться с задержкой и иногда уменьшаться после корректировок YouTube. Сервис не восстанавливает историю до первого запуска и не делает предположений о монотонном росте просмотров. Одновременно запускайте один сборщик для одного файла базы.

### Квота

У проекта YouTube Data API обычно есть 10 000 единиц квоты в сутки. Каждое чтение `channels`, `playlistItems` или `videos` стоит 1 единицу; дорогой `search.list` не используется. Квота общая для всего Google Cloud проекта, включая другие приложения; её фактический лимит проверьте в Google Cloud Console.

При `B` партиях статистики (по 50 видео), `P` страницах загрузок, интервале сбора `I` минут и интервале полного обхода `D` минут приблизительный расход за сутки:

```text
ceil(1440 / I) × (1 + B) + ceil(1440 / max(I, D)) × (P − 1) + 1
```

Здесь последняя единица — получение плейлиста канала при запуске. Для примера, **20 страниц** и **до 50 отслеживаемых видео**, с полным обходом раз в час: сбор каждую минуту расходует около **3 337 единиц в сутки**, раз в 5 минут — около **1 033**. Это расчёт для примера, а не измеренный размер канала. Повторы запросов и частые перезапуски увеличивают расход; если нет подходящих видео, запрос статистики пропускается.

По умолчанию установлен интервал 5 минут с полным обходом канала раз в час. Эти значения можно изменить в `.env`:

```dotenv
POLL_INTERVAL_MINUTES=5
FULL_DISCOVERY_INTERVAL_MINUTES=60
```

При увеличении срока отслеживания растёт число партий статистики, а при увеличении канала — число страниц полного обхода. Автоматического ограничения общего расхода других приложений проект не обеспечивает. HTTP 403 `quotaExceeded` фиксируется в логах; после сброса квоты следующие циклы снова смогут собирать данные. Квота YouTube сбрасывается в полночь по тихоокеанскому времени США.

Официальная документация: [playlistItems.list](https://developers.google.com/youtube/v3/docs/playlistItems/list), [videos.list](https://developers.google.com/youtube/v3/docs/videos/list), [расход квоты](https://developers.google.com/youtube/v3/determine_quota_cost).

## Проверки

Автоматические тесты работают без реального ключа. Они проверяют границу срока и его изменение, историю и перезапуск SQLite, пагинацию и партии API, обработку недоступных видео и ошибок, повторные запросы, отсутствие пересечения циклов и завершение по сигналу. Интеграционный тест использует локальный HTTP-сервер с ответами в формате YouTube API и проходит полный путь от обнаружения видео до записи и экспорта истории.

Для проверки реального канала после настройки ключа выполните `npm run collect`, затем `npm run --silent export`. Если за выбранный период публикаций нет, цикл корректно сохранит ноль наблюдений. Само наличие запущенного процесса ещё не означает успешный сбор: проверьте `collection_completed` и CSV.
